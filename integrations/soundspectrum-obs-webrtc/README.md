This experiment replaces the existing JPEG video bridge only when the user selects **OBS WebRTC**. The normal transport remains available. The separate provider owns its own portable OBS profile, scene collection, authenticated control server and MediaMTX relay under ignored `data/soundspectrum-obs-webrtc/`. It does not alter installed OBS or the user's OBS profiles.

The path is the actual owned Aeon, G-Force or WhiteCap window → OBS Window Capture using Windows Graphics Capture → NVENC H.264 → local WHIP publisher → MediaMTX → same-origin WHEP signaling and WebRTC video in the browser. MediaMTX forwards the compressed stream without transcoding. Capture uses the client area, excludes the cursor, and forces SDR. It does not inject into the visualizer.

The default `1080p60` profile uses a 1920 × 1080 canvas and output at 60 fps with a 25 Mbps CBR target. The optional private `4k60` profile uses 3840 × 2160 at 60 fps with an 80 Mbps CBR target; `4k60-60` retains that exact 4K60 geometry with a 60 Mbps CBR target. Both 4K profiles request a native borderless fullscreen client area for each product. All use NVENC H.264, P5, low latency tuning, no B-frames or lookahead, NV12, 8 bit 4:2:0, and Rec.709 limited range. These are configuration values. The browser's received coded resolution, codec and RTP rate are separate measurements. Each visualizer's internal framebuffer precision is unknown.

Both 4K profiles require the initial native client area and OBS source to be genuinely 3840 × 2160; they fail rather than enlarging a 1080p source and calling that native 4K. Later manual native resizing remains visible in the measurements and OBS fits that client area inside the fixed canvas, which can introduce scaling or bars. Changing the private quality profile during an active session does not reconfigure it: Stop and Start are required, and a changed profile between backend inspection and startup is rejected before acquiring helper ownership.

The 80 Mbps target is an experimental quality choice, not a universal browser or Wi-Fi guarantee. A tablet must actually decode and receive 4K60 successfully for that path to be considered verified. H.264 remains lossy; this experiment does not promise pixel-identical output or HDR. OBS's separate lossless encoder mode and CQP mode are different, and encoding the converted NV12 image losslessly would still not preserve the native RGB image's full chroma. The browser transport therefore retains ordinary H.264 without B-frames; a mathematically lossless native-image path would require a separate capture, pixel-format and decoder design.

No desktop, microphone, or window audio capture is enabled. OBS's ordinary streaming frontend creates a silent Opus track; browser offers request video only. The music and the existing HQPlayer analysis route retain their existing ownership.

## Preparation

Use `prepare.ps1` from this directory with a private LAN IPv4 address. It downloads pinned official archives, verifies their SHA-256 hashes, and extracts a separate portable runtime. It prepares files only and does not launch OBS, MediaMTX, G-Force, audio, playback, or firewall changes. It refuses to overwrite an existing runtime or ownership lock.

```powershell
powershell.exe -NoProfile -File integrations/soundspectrum-obs-webrtc/prepare.ps1 -LanAddress 192.168.1.100
```

`runtime.json` contains version 1, `obsVersion`, `mediaMtxVersion`, absolute `obsRoot`, `obsExecutable`, `relayExecutable`, `lanAddress`, and distinct `ports` for `obs`, `http`, `api`, and `udp`. Defaults are 4565, 8899, 9996, and 8199. Optional `qualityProfile` accepts only `1080p60`, `4k60` or `4k60-60`; omission retains `1080p60`. Select it only after visuals have stopped and owned helper cleanup has completed, then use the supported service restart to load the changed inventory before Start. No passwords are stored in this preparation manifest. Startup generates private per-session credentials and a random publisher path.

MediaMTX ingestion and API listen on loopback. Its ICE UDP port allows browser media on the configured LAN address. OBS's bundled WebSocket listener has no loopback binding setting, so its separate control port requires a random per-session password. No firewall rule is created. If Windows blocks the private UDP listener, the LAN viewer cannot connect; do not describe that as a successful fidelity test.

## Ownership and cleanup

Import and `inspect()` only read preparation files. Start requires a current Rabbit Hole generation and its exact owned native PID, HWND, executable and start identity. The native controller temporarily gives that window a UUID title. The provider checks OBS's selectable window values for exactly that title, class and executable, uses title-only matching, and fails closed if the window cannot be selected uniquely. It periodically checks the owned identity and publisher activity.

The UUID title identifies the product as well as the session; its product must
match the exact Standalone executable. Native fullscreen preparation verifies
the observed HWND, class and original title before applying borderless sizing.
Aeon and WhiteCap use the same source/output size guards and encoder profile as
G-Force. No desktop-wide or approximate title matching is introduced.

In Rabbit Hole's Visuals & audio dialog, select a visualizer and **OBS / WebRTC**.
Switching visualizers retains that selected transport. A fresh browser with no
saved transport prefers OBS when the prepared runtime and receiver are available;
an explicit saved JPEG choice is preserved. Unavailable OBS remains selected
with a reason, and failures never silently start JPEG. Saved choices never start
visuals by themselves. This module belongs to the main Rabbit Hole app; the
separate Roon Visualizer application on port 3788 has its own implementation.

Only the two helper processes created by this provider are released. Verified PID, executable and process start time are required for termination; a spawn whose identity cannot be read is released through its own Node process handle. Cleanup runs before Rabbit Hole releases the native renderer and audio analysis. An ownership lock and record prevent a second owner; a failed cleanup preserves them for inspection. Do not delete a leftover ownership lock until its exact recorded processes have been checked. There is no automatic recovery that terminates an unrelated OBS process.

WHEP readers are limited to eight. Each viewer can own one reader and one pending replacement. Same-origin signaling exposes an opaque reader token, never the local relay location or credentials. Viewer release, lease expiry, and Stop clean those resources. Startup and signaling responses are bounded; redirects are rejected.

Private OBS logs are in the portable `obs/config/obs-studio/logs/` directory. Relay warnings are written inside the ignored runtime `logs/` directory. Logs may contain private addresses and publisher paths; do not publish them or return raw logs through the diagnostic endpoint. The diagnostic caches OBS-reported source dimensions and transforms, OBS output settings, the MediaMTX H.264 track identity, and publisher byte-counter rate windows. Its publisher rate includes the silent Opus track; browser video RTP bitrate is measured separately.

Run offline checks without starting any video or audio:

```powershell

```

## Removal

Stop visuals first and let owned helper cleanup complete. Select the normal JPEG transport. The optional provider can then be removed by deleting this module and its ignored runtime directory; the backend treats a missing optional provider as unavailable. Remove the optional transport choice and receiver scripts if removing the experiment permanently. No installed OBS profile, SoundSpectrum installation, Roon, or HQPlayer setting belongs to this module.
